# OpenFold2 technical specification

BIO-006, proposed design. Handwritten integration, not a generated model. Scientific and managed qualification remain incomplete.

Use NVIDIA's HTTPS endpoint `/v1/biology/openfold/openfold2/predict-structure-from-msa-and-template` at health.api.nvidia.com. The model itself runs remotely; local CPU resources describe only the client. NVIDIA_API_KEY must already be securely provisioned in the worker environment. Never store it in a Lab, request artifact or result. Disable redirects and environment proxies. Observe accepted calls only by the returned UUID using NVIDIA's status route; resume requires the original canonical request SHA-256 and UUID. No automatic retry on HTTP 500, timeouts, missing outputs or contract failures. The first real request failed with a provider CUDA illegal-memory-access error; this is preserved as evidence, not repaired by changing the scientific input.

Proposed inputs, mixed symbolic envelope unit 1:

- protein_sequence: required scalar str, 1–1000 standard uppercase residues. No normalization or padding.
- protein_msa: optional record `{query:json,alignments:json}`, default empty query and list. Nonempty input follows the MSA Search collection representation: exact query sequence/hash and per-database format/text/byte hash entries. Accept A3M only; preserve each native text. Check query identity, insertion-aware match columns and no duplicate database/format entries. Paired collections require an explicit separately reviewed chain selector. Empty MSA is visibly recorded as sequence-only mode, not filled with invented hits.
- templates: optional record `{items:json}`, default empty. Each item is a complete uncompressed mmCIF string plus SHA-256, name, source and provenance. Parse entity/chain identifiers and finite atom coordinates, require a label chain A, retain intact contents and record native template mapping as unexposed. Format mmcif.gz and binary/base64 conventions need their own integration test; current explicit text path uses mmcif. Native HHR processing is removed in 2.x.
- run_options: optional record `{parameters:json}`, defaults selected_models=[1,2,3,4,5], use_templates=false, relax_prediction=false. Validate unique selected_models integers 1–5; no bool integers, unsupported seeds or arbitrary upstream options. Current NIM relaxation must remain false. Template enablement and provided templates must agree so inputs are not silently ignored.
- query_metadata: optional record `{query_id:str,provenance:json}`; content-addressed ID when absent, otherwise bounded to native input_id 128 characters. Distinguish user-supplied evidence from verified wrapper checks.

Proposed required outputs:

- predicted_structure: record `{query:json,structures:json}` containing every ranked native model, unchanged structure text, format, artifact bytes/SHA-256, rank/parameter-set identity, atom coordinates in angstrom and residue-to-query mapping. PDB or mmCIF serialization does not establish the scientific provenance by itself.
- confidence_scores: record `{records:json,semantics:json}` preserving native confidence and optional pLDDT/PAE/pTM fields and their availability. pLDDT scale 0–100, PAE angstrom, pTM dimensionless. The generic ranking confidence remains native/definition-unverified. Native PDB B-factors are retained without silently treating them as independently verified pLDDT. A2.6 deprecated aligned_confidence_probs may be null; a missing field is not converted into a fabricated populated tensor.
- inference_metrics: record `{native:json,semantics:json}` for original performance metrics, with units only where documented. Distinguish wall seconds from biological time.
- run_provenance: record `{request:json,provider:json,inputs:json,backend_identity:json,limitations:json}` binding exact input, structure hashes and provider UUID. Missing checkpoint/container/GPU identities remain null. Template and MSA evidence hashes are retained; they do not imply training-data independence.
- native_response: scalar str containing exact UTF-8 response JSON.

Validate top-level handled-error status before accepting predictions. Require expected selected parameter-set identities, contiguous zero-based rank semantics, finite coordinates and exact query/structure correspondence. Do not report only the easiest/top-ranked model and silently discard the rest. Per-residue/per-pair tensors need dimensions matching the query, finite values and appropriate domains; null/absent availability is preserved. No arbitrary numerical reference-match tolerance or confidence-to-accuracy transformation.

Default client bounds: 600 seconds observation and 20 MB decoded response. Observation expiry does not cancel remote compute. Input/template/structure sizes must be bounded before network use; limits are client constraints, not alleged NVIDIA model limits. Use Python 3.10 and exactly pinned installed packages. Local tested runtime 0.0.34, source runtime 0.0.35, historical skill 0.0.27 and actual managed runtime are separate facts. Proposed profile declarations stay absent until released checkers and target runtime support are established.

Identity: current model card OpenFold2 2.6.0 release date 2026-09-01, hosted published API schema 2.1.0. The card still mentions HHR and ≤1000 residues while NIM 2.6 removes HHR and reports ≤2048 hardware support. Do not resolve conflicts by inventing a deployed version. The card attributes parameter sets to AlphaFold2 development; this is not a checkpoint digest. Review NVIDIA API Trial terms, NVIDIA Open Model Agreement, upstream Apache 2.0 information and actual weight/container terms separately.

Self-hosted support matrix: one supported NVIDIA GPU (including 40/80GB A100 and 48GB L40S), at least 8 CPU cores, 64GB RAM, 80GB disk; approximately 5.2GB parameter cache. No model, weights, container or runtime was downloaded/installed for this integration.
